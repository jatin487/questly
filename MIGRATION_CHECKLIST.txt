═════════════════════════════════════════════════════════════════════════════
                         TROUBLESHOOTING SECTION
═════════════════════════════════════════════════════════════════════════════

PROBLEM: "Images not uploading"
  Solution:
    1. Check mission-submissions bucket exists
    2. Verify bucket privacy is set to Public
    3. Confirm NEXT_PUBLIC_SUPABASE_URL is correct
    4. Restart dev server: npm run dev

PROBLEM: "404 errors on image URLs"
  Solution:
    1. Verify bucket is set to Public (not private)
    2. Check image actually exists in bucket
    3. Confirm URL format (no extra spaces)
    4. Check NEXT_PUBLIC_SUPABASE_URL in environment

PROBLEM: "Can't find API keys in Supabase"
  Solution:
    1. Go to: https://app.supabase.com/projects
    2. Select your project
    3. Click Settings (gear icon in left sidebar)
    4. Click "API" in the settings menu
    5. Keys are under "Project API keys" section

PROBLEM: "Environment variables not taking effect"
  Solution:
    1. For local: Stop dev server and run npm run dev again
    2. For Vercel: Manual redeploy or wait for auto-deployment
    3. Clear browser cache (Ctrl+Shift+Delete)
    4. Check for typos in variable names

PROBLEM: "Users getting 'Unauthorized' errors"
  Solution:
    1. Verify NEXT_PUBLIC_SUPABASE_ANON_KEY is correct
    2. Check it starts with "eyJ" (JWT format)
    3. Confirm no extra spaces in the key
    4. Try creating a new test user

PROBLEM: "Old images still showing"
  Solution:
    1. This is normal - old images reference old project
    2. New images go to your new project
    3. To migrate old images, manually copy bucket files
    4. Or just accept that new content goes forward
